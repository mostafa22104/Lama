# Lamma — Phase 3: Owner App Foundation (React Native) — Design

- **Date:** 2026-10-11
- **Status:** Draft — awaiting review
- **Parent spec:** `docs/superpowers/specs/2026-10-11-lamma-architecture-design.md` (sections 2, 3, 4, 6; phase 3 of section 8). This document refines it for Phase 3; where they differ, this one wins for Phase 3.
- **Design source:** `lamma-design-handoff/` — `Signup`, `Components`, bottom nav in `Home`.

## 1. Goal and scope

Create `apps/mobile`, the owner app, with everything later phases build on, and a working sign-up / login against the Phase 1–2 backend.

**In scope**
- React Native CLI app, Android verified (iOS code kept cross-platform but not built — needs macOS).
- Theme (light / dark / system), fonts, `useTheme` + `makeStyles`.
- i18n (Arabic default, English) with RTL/LTR switching.
- Shared components from the `Components` sheet.
- Navigation: auth stack and the 4 main tabs (placeholder tab screens).
- Auth: Signup (step 1/4), Login, OtpVerify; secure token storage; automatic refresh; session restore.
- A debug-only component gallery used to verify components and to switch theme/language.

**Out of scope (Phase 4+)**: onboarding steps 2–4, real tab screens, Settings (theme/language/logout move there), push notifications, iOS build.

**Done when**
1. The app builds and runs on the Pixel emulator.
2. An owner can sign up and log in with an OTP from the backend log, land on the tabs, and stay signed in after killing and reopening the app.
3. Every shared component renders correctly in light/dark × Arabic/English (checked in the gallery with emulator screenshots).
4. `yarn lint` and all tests pass.

## 2. Decisions

| Topic | Decision |
|---|---|
| App id / name | Android package and iOS bundle id `com.lamma.owner`; launcher name «لمّة» (English: Lamma) |
| Framework | React Native 0.87 CLI, TypeScript, New Architecture on |
| Toolchain | JDK 17, Android SDK 35/36, emulator Pixel 6/7 (all present on the dev machine) |
| Monorepo | `apps/mobile` is a Yarn workspace; Metro watches `packages/shared` and resolves `@lamma/shared` |
| Navigation | React Navigation 7 (native stack + bottom tabs), typed route params |
| Server state | TanStack Query 5 |
| Client state | Zustand 5 (`auth`, `theme`, `language`), persisted with MMKV (theme, language only) |
| Secrets | Refresh token in Android Keystore via `react-native-keychain`; access token in memory only |
| HTTP | axios client with token attach + single-flight refresh |
| i18n | i18next + react-i18next using `@lamma/shared` `resources`; Arabic default regardless of phone language |
| RTL | `I18nManager.forceRTL` + `react-native-restart` on language change; consistency check at startup |
| Icons | `react-native-svg` + `lucide-react-native` (stroke 2, 24 viewBox — matches the design) |
| Fonts | IBM Plex Sans Arabic 400/500/600/700 bundled (OFL), one font file per weight |
| Forms | `react-hook-form` + `zod`, validated with shared normalizers |
| Tests | Jest + React Native Testing Library; MSW for API mocking |
| UI verification | Debug-only component gallery + emulator screenshots via `adb exec-out screencap` |
| API base URL | Debug: `http://10.0.2.2:3000/api/v1` (emulator alias for the host); release: injected at build time (no hardcoded production URL) |

## 4. Theme, language, RTL

- `theme-store` `{ mode: 'light' | 'dark' | 'system' }` persisted in MMKV; `system` follows `useColorScheme()` live.
- `useTheme()` → `{ name, colors, status, type, radius, sizes, spacing }` from `@lamma/shared` tokens. `makeStyles(fn)` returns a hook that memoizes styles per theme name.
- `Text` variants map to `TYPE_SCALE` with per-weight font families (`IBMPlexSansArabic-Bold` etc.); line height = size × ratio.
- Status bar style and Android navigation bar color follow the theme.
- `language-store` `{ language: 'ar' | 'en' }` persisted in MMKV, default `ar`. `setLanguage()` saves, calls `I18nManager.allowRTL(true)` / `forceRTL(isRtl(lang))`, then `RNRestart.restart()`. At startup, if `I18nManager.isRTL !== isRtl(saved)`, apply and restart once.
- Layout uses logical properties (`start/end`, `marginStart/End`, `paddingStart/End`); directional icons (back arrow, chevrons) mirror via a `mirrored` prop on `Icon`.
- Digits: amounts via shared `formatAmount` (Western digits); phones, OTP codes and InstaPay addresses always LTR (`writingDirection: 'ltr'`).
- New shared copy (in `packages/shared/src/i18n`): an `auth` namespace (screen titles, labels, hints, buttons, OTP texts) and `common.network` («مفيش إنترنت، جرّب تاني» / "No internet connection, try again"). Copy for Signup is taken verbatim from `screens/Signup.html`.

## 5. Shared components (from the `Components` sheet)

`Screen` (safe area, scroll, 16 px gutter, keyboard-aware), `Text`, `Icon`, `Button` (primary / whatsapp / outline / danger-outline / ghost; 56 px / 52 px; loading + disabled states), `TextField` (label, hint, error), `PhoneInput` (LTR), `AmountInput` (ج.م suffix), `OtpInput` (6 boxes, paste, Arabic digits, auto-submit), `SegmentedControl`, `ChipSelect`, `StatusChip`, `AmountText`, `Card`, `Avatar` (initial + tint), `CustomerRow`, `Toggle`, `ProgressBar`, `Badge`, `StepHeader` (back + title + 4-step bar + «خطوة X من 4»), `EmptyState`, `Skeleton`.

Each component has an RNTL test (renders, accessibility label/role, key interactions) and appears in the gallery. Minimum tap target 44 px; primary buttons 56 px.

## 6. Navigation and auth flow

- `RootNavigator` reads `auth-store.status`: `restoring` → splash (theme background + logo); `signedOut` → `AuthStack`; `signedIn` → `MainTabs`.
- `AuthStack`: `Signup` (initial) · `Login` · `OtpVerify`. `MainTabs`: Home · Customers · Confirmations · Reports, custom `TabBar` per the design (72 px, active pill, badge slot). Debug builds add a `ComponentGallery` stack screen reachable from the Home placeholder.
- **Signup** (design copy): channel toggle → contact field, business name, business type chips, InstaPay address + hint, «كمّل». Local validation with shared `normalizeContact`; on submit → `POST /auth/otp/request` → `OtpVerify` with `{ channel, contact, signup }`. Link «عندك حساب؟ ادخل» → Login.
- **Login**: channel toggle + contact → request OTP → `OtpVerify` with `{ channel, contact }`.
- **OtpVerify**: shows the masked contact; 6-box input; auto-submits on 6 digits → `POST /auth/otp/verify`. Resend link with 60 s countdown (started on entry and on `OTP_COOLDOWN`). Errors: `OTP_INVALID`, `OTP_EXPIRED`, `OTP_TOO_MANY_ATTEMPTS` shown inline via `t('errors:…')`. `SIGNUP_REQUIRED` → message «الرقم ده مش متسجّل» + «اعمل حساب» → `Signup` prefilled with the contact and carrying the already-entered code; completing Signup then calls verify directly with that code (no new OTP).
- **Session**: on verify success → keychain stores refresh token; store holds access token + business; status `signedIn`. App start: read refresh token → `POST /auth/refresh` → `signedIn` (fetch `GET /business`) or `signedOut`. axios: attach `Bearer`; on `401 TOKEN_INVALID` run one shared refresh, retry the request once; refresh failure → clear tokens → `signedOut`. Logout (gallery for now): `POST /auth/logout`, clear keychain, `signedOut`.
- **Errors**: every API failure becomes `AppError { code: ErrorCode | 'NETWORK' }`; screens render `t('errors:'+code)` or `t('common:network')`.

## 7. Testing and verification

- Jest + RNTL + MSW: shared components; theme/language stores; `apply-direction`; `makeStyles` memoization; axios refresh (single flight, retry once, sign-out on failure); session restore; Signup validation (Arabic-digit phone, required fields); OtpVerify (paste, auto-submit, countdown, `SIGNUP_REQUIRED` path); architecture test for `src/features`.
- Manual acceptance on the Pixel emulator against the local backend, with screenshots saved under `.superpowers/` scratch: sign-up → OTP from backend log → tabs; restart app → still signed in; gallery in light/dark × ar/en; logout.

## 8. Risks

- **Metro + Yarn workspaces + ESM shared package**: Metro must resolve `@lamma/shared`'s `exports` and the `.js`-suffixed ESM imports in its `dist`. Mitigation: verify in the first task; fall back to a Metro `resolver.extraNodeModules` / `unstable_enablePackageExports` setting.
- **Hermes + `Intl`**: shared `toBusinessDate` uses `Intl.DateTimeFormat` with `timeZone: 'Africa/Cairo'`, and `formatAmount` uses `Intl.NumberFormat`. Verify Hermes support in the first task; if missing, ship the `@formatjs` polyfills for DateTimeFormat (with Africa/Cairo tz data) and NumberFormat.
- **RTL restart**: forced RTL changes apply only after restart; covered by the startup consistency check.
- **Windows build paths**: long paths in Gradle/CMake on Windows; keep the repo at `C:\dev\Lama` (short) and enable long paths if a build fails.
